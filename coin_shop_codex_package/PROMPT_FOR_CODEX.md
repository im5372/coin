# Codex에 그대로 넣을 작업 지시문

이 프로젝트는 초등 특수학급 공개수업에서 사용할 화폐 학습 웹게임이다.

먼저 `README_FIRST.md`를 읽고, `references/02_target_reference_screen.png`를 **최종 디자인의 최우선 기준**으로 삼아라. `references/01_current_actual_screen.png`는 현재 구현이 왜 부족한지 비교하는 자료다.

`src/index.html`을 기반으로 전면 리디자인하되, 필요하면 `src/stable_logic_baseline.html`에서 안정적인 drag & drop 로직을 가져와도 된다.

## 가장 중요한 목표

단순한 HTML 카드 UI나 네모 박스 여러 개를 조립한 웹페이지처럼 보이면 안 된다. 가게 내부, 가게 주인, 상품, 말풍선, 손바닥, 동전함이 **하나의 모바일 교육용 게임 장면**처럼 자연스럽게 연결되어야 한다.

화면은 약 390x844 세로형 스마트폰을 기준으로 중앙 정렬한다. 전체 웹창을 반드시 채울 필요는 없다.

## 캐릭터와 결제

- 가게 주인은 카운터 뒤에서 크게 보인다.
- 가게 주인은 학생 쪽으로 손바닥을 내민다.
- 학생은 실제 100원/500원 이미지를 아래 동전함에서 손바닥 위로 drag & drop 한다.
- 손바닥에 올라간 동전도 다시 동전함으로 끌어오면 제거된다.
- 100원은 500원보다 작게 보인다.

## 학생별 문제

### 지오
- 300원 → 500원 → 700원
- 1,2번 숫자면
- 3번 그림면
- 500원 동전 사용을 강제하지 않는다.
- 합계가 정확하면 어떤 조합도 정답이다.

### 하리
- 200원 → 600원 → 800원
- 3문제 모두 **숫자면만** 보여준다.
- 500원 사용을 강제하지 않는다.
- 합계만 정확하면 정답이다.

### 하준
- 동전과 물건의 교환 개념 중심
- 동전 하나를 가게 주인 손바닥에 주면 성공
- 성공하면 상품이 가게 주인/카운터 쪽에서 학생이 받는 위치로 이동하는 애니메이션을 보여준다.
- '동전을 주면 물건을 받는다'가 명확히 느껴져야 한다.

## 중요 용어

이 프로젝트에서 사용자 기준:
- 앞면 = 숫자면
- 뒷면 = 그림면

코드 내부는 혼동을 피하려면 `numberSide`, `pictureSide` 같은 이름을 사용하라.

## 피드백

- 부족: "돈이 조금 부족해요."
- 초과: "돈이 너무 많아요."
- 정답: 축하 효과 + 상품 구매/교환 애니메이션
- 실패를 강하게 표현하지 말고 다시 시도하도록 유도

## 구현 품질

- 태블릿 터치를 최우선으로 한다.
- Pointer Events 사용을 권장한다.
- 화면을 실제 브라우저에서 열어 레이아웃을 확인하라.
- `references/02_target_reference_screen.png`와 시각적으로 비교하면서 반복 수정하라.
- 기능이 동작하더라도 시각적으로 카드형 웹페이지처럼 보인다면 완료로 보지 말라.
- 최종 결과물은 인터넷 없이 실행 가능해야 한다.

작업 후에는 변경한 내용과 실행 방법을 짧게 정리하라.
