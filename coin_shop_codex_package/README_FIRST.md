## 중요: 이 프로젝트에서의 동전 면 명칭

사용자와 수업에서는 아래처럼 부릅니다.

- **앞면 = 숫자면** (`100`, `500`이 크게 적힌 면)
- **뒷면 = 그림면** (100원: 이순신, 500원: 학)

일반적인 주화 용어와 다를 수 있지만, **이 프로젝트에서는 반드시 위 용어를 사용**해 주세요.

파일명도 혼동을 막기 위해 `number_side`, `picture_side`로 정리했습니다.

## 학생별 게임 요구사항

### 지오 (A 수준)
- 1번: 300원
- 2번: 500원
- 3번: 700원
- 1, 2번은 **숫자면** 사용
- 3번은 **그림면**을 보고 해결하는 문제
- 500원 사용을 강제하지 않음
- 100원만 사용해 정확한 금액을 만들어도 정답
- 핵심: 가격에 맞는 금액 구성

### 하리 (B 수준)
- 1번: 200원
- 2번: 600원
- 3번: 800원
- **모든 문제에서 숫자면만 사용**
- 500원 사용을 강제하지 않음
- 어떤 조합이든 정확한 가격이면 정답
- 핵심: 100원과 500원을 이용한 금액 구성

### 하준 (C 수준)
- 수 개념보다 **동전과 물건의 교환 개념**이 핵심
- 동전을 가게 주인의 손바닥에 드래그하면 결제 성공
- 결제 성공 후 상품이 가게 주인 쪽에서 학생/받는 영역 쪽으로 **실제로 이동하는 애니메이션** 제공
- '동전을 주면 물건을 받을 수 있다'가 직관적으로 보여야 함

## 공통 조작 요구사항

- 태블릿/스마트패드 터치 우선
- 동전을 **가게 주인의 손바닥으로 drag & drop**
- 손바닥에 올린 동전도 다시 동전함으로 drag & drop하여 제거 가능
- 100원은 500원보다 시각적으로 작게 표시
- 사용자가 제공한 실제 동전 이미지를 사용
- 가격보다 많음 / 부족함 / 정답 피드백 제공
- 정확한 합계만 맞으면 정답
- 오답은 실패 화면보다 '다시 생각해 보기'식 안내

## 시각 디자인 핵심

`references/02_target_reference_screen.png`를 기준으로 합니다.

- 390x844 정도의 세로형 스마트폰 화면을 기준으로 하되 완전 고정일 필요는 없음
- 화면 중앙에 모바일 게임이 놓인 느낌
- 가게 내부가 하나의 배경 장면으로 이어져야 함
- 가게 주인이 크게 보여야 함
- 상품은 카운터 위에 실제로 놓인 느낌
- 말풍선이 캐릭터에게 자연스럽게 연결
- 손바닥 자체가 결제 드롭 영역처럼 보이게 함
- 동전함은 화면 하단에 자연스럽게 배치
- 흰색 카드/네모 박스를 여러 개 이어 붙인 웹페이지 느낌을 피함
- 기능을 보여주기 위해 캐릭터를 작게 만들지 말 것
- UI 텍스트는 초등 저학년이 보기 쉽게 크고 짧게

## 개발 방식 권장

- 가능하면 `index.html` + 로컬 assets 구조로 유지
- 인터넷 연결 없이 실행 가능하게 만들기
- Pointer Events를 이용해 mouse/touch 모두 대응
- 브라우저에서 실제로 실행해 타깃 참고 이미지와 반복 비교
- 먼저 레이아웃/비주얼을 맞춘 뒤 기능을 연결
